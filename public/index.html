Authentication

        
Send your credential on every request except GET /health, the console and the pairing routes. Either header works:

        

        

          
CredentialWhere it comes fromNotes

          
            
wa_… device tokenMinted when a phone completes pairingStored only as a SHA-256 hash. Revoked by /logout and /tokens/revoke

            
Admin keyAPI_KEY in .envNever expires, survives logout. Use it for scripts and cron

          
        

        
Pairing routes need no credential from 127.0.0.1. From any other address they require the admin key, unless ALLOW_REMOTE_PAIRING=true.

Recipient formats

        
The to field takes loose input and is normalised for you. Digits are stripped of punctuation, a leading 00 is dropped, and the result must be 7–15 digits including the country code.

        

          
You sendIt becomes

          
            
+91 98765 43210919876543210@s.whatsapp.net

            
(91) 98765-43210919876543210@s.whatsapp.net

            
0091 98765 43210919876543210@s.whatsapp.net

            
919876543210@c.us919876543210@s.whatsapp.net

            
120363021234567890@g.uspassed through unchanged (group)

          
        

        
A local number without a country code will reach the wrong person or nobody. @broadcast and status@broadcast are rejected.

      


      

        
Incoming messages (webhook)

        
Set WEBHOOK_URL and every inbound message is POSTed there as JSON. Your own messages (key.fromMe) and status broadcasts are skipped, and only notify-type events are forwarded — not history sync.

        

        

          
FieldMeaning

          
            
fromThe chat. A group JID for groups, the sender for 1:1

            
participantWho actually sent it. In a 1:1 chat this equals from

            
isGrouptrue when from ends in @g.us

            
typeBaileys message key: conversation, extendedTextMessage, imageMessage, documentMessage, … Ephemeral and view-once wrappers are unwrapped first

            
textBody or caption, or null for messages with no text

            
timestampUnix seconds, as sent by WhatsApp

          
        

        
If WEBHOOK_SECRET is set it arrives as the x-webhook-secret header — check it before trusting the payload. Delivery retries up to WEBHOOK_MAX_ATTEMPTS times with 500ms/1s/2s backoff; a 4xx other than 408/429 is treated as permanent.

      


      

        
Rate limiting

        
Every outgoing send passes through one serial queue that guarantees at least SEND_DELAY_MS (default 3000ms) between two sends. This is deliberate: firing messages back to back is what gets numbers banned.

        
    
          
  • 202 Accepted means queued and handed to WhatsApp, not delivered.
    • 
          
  • At the default delay, 20 queued messages take about a minute to drain.
    • 
          
  • Once MAX_QUEUE_SIZE messages are waiting, further sends fail fast with 503 instead of growing memory. Watch queued in GET /status.
    • 
          
  • A queued message whose socket drops fails with 503 rather than being sent late on a new connection.
    • 
        

      


      

        
Errors

        
Every error is JSON in the same shape:

        

        

          
StatusCodeWhen

          
            
400bad_requestMalformed JSON, missing field, bad number or URL

            
401unauthorizedMissing or wrong credential; or remote pairing attempt

            
404not_foundNo such route

            
409conflict/qr or /pair/start while already linked

            
500internal_errorUnexpected. Details are logged, never returned

            
502upstream_errorWhatsApp did not acknowledge the message

            
503service_unavailableNot linked, no QR yet, or the send queue is full
